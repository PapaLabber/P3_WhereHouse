End-to-end system test (frontend + backend)

This folder contains a Playwright-based E2E test that exercises the full flow:
- Frontend UI (running at http://localhost:3000)
- Backend (running at http://localhost:8080 inside Docker)
- Upload an autogenerated `.xlsx` fixture
- Wait for the frontend to download the produced results
- Inspect the downloaded file and the backend `./outputFile` folder

Quick start (PowerShell):

1) From the repository root, build and start services via Docker Compose:

```powershell
cd .\e2e
npm install
npm run start:services
```

2) Wait until the frontend+backend are healthy (the `e2e` script uses `wait-on` to check `http://localhost:3000`).

3) Run the tests:

```powershell
npx playwright test
```

4) When finished, stop the services:

```powershell
npm run stop:services
```

Or run the convenience script which starts services, runs tests and stops them:

```powershell
npm run e2e
```

Notes:
- The backend Docker image uses the project's `backend/Dockerfile`. The `pom.xml` already depends on `com.google.ortools:ortools-java`; the Docker build will include that dependency. Ensure your Docker host is x86_64 Linux compatible (CI runners usually are).
- If OR-Tools native libs cause issues in CI, consider ensuring the Docker image uses a compatible base image or installing native packages as needed.
